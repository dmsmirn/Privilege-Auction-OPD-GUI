# STATA — интерфейс аукциона привилегий

Фронтенд проекта «Аукцион привилегий» (ОПД). Пользователь выполняет задачи, получает за них баллы и тратит их на аукционе привилегий. Сайт только показывает данные и отправляет запросы. Баллы и ставки считает сервер на C++, а формулы берутся из библиотеки `pa::Engine` (репозиторий `Privilege-Auction-OPD`).

## Что нужно установить

| Программа | Версия | Проверить |
|---|---|---|
| Node.js | 20.19 или новее | `node -v` |
| npm | ставится вместе с Node.js | `npm -v` |
| git | любая свежая | `git --version` |
| Компилятор C++ (для сервера) | с поддержкой C++17: clang на Mac, g++ на Linux, Visual Studio на Windows | `clang++ --version` |

На Mac компилятор ставится командой `xcode-select --install`.

## Быстрый старт

Нужны два окна терминала: в одном работает сервер, в другом сайт.

**Окно 1 — сервер.** Нужны файлы `server_contract.cpp`, `httplib.h` и `json.hpp` в одной папке:

```
clang++ -std=c++17 server_contract.cpp -o server_contract -pthread
./server_contract
```

Сервер запустится на http://localhost:8080. Окно не закрывайте, пока работаете.

**Окно 2 — сайт:**

```
git clone https://github.com/Privilege-Auction/Privilege-Auction-OPD-GUI.git
cd Privilege-Auction-OPD-GUI
npm install
npm run dev
```

Откройте http://localhost:5173. Остановить сайт или сервер — `Ctrl+C` в его окне.

> Вход и регистрация пока работают без сервера: подойдут любая почта и пароль от 4 символов.

## Как сайт связан с сервером

```
Браузер  →  сайт (React, порт 5173)  →  /api/...  →  сервер C++ (порт 8080)  →  библиотека pa::Engine
```

- Сайт обращается к адресам вида `/api/tasks`, без адреса сервера.
- Во время разработки Vite сам пересылает такие запросы на `http://localhost:8080` (настройка `server.proxy` в `vite.config.ts`).
- На готовой версии сайт и API отдаются с одного адреса (см. «Запуск одной программой»), поэтому код сайта менять не нужно.

Сейчас вместо финального сервера используется **заглушка** `server_contract.cpp`: тестовые данные, все адреса из контракта и формула награды из библиотеки. Когда сервер подключит `pa::Engine`, сайт продолжит работать без изменений.

## Сборка интерфейса

```
npm run build
```

Что происходит:

1. TypeScript проверяет типы (`tsc -b`). Если есть ошибка, сборка останавливается и показывает, где она.
2. Vite упаковывает код, стили, логотип и шрифты в папку `dist/`:

```
dist/
├── index.html        единственная HTML-страница
├── favicon.svg       значок вкладки
└── assets/           JavaScript и CSS с хешем в имени (index-a1b2c3.js)
```

Папка `dist/` — это готовый сайт из статических файлов. Её можно:

- выложить на любой хостинг (Vercel, Netlify, GitHub Pages);
- отдавать из C++-сервера вместе с API (следующий раздел).

Важно:

- `dist/` не хранится в репозитории (она в `.gitignore`) и создаётся заново при каждой сборке.
- Открывать `dist/index.html` двойным кликом нельзя: страницам нужен веб-сервер. Для проверки используйте `npm run preview` или запуск одной программой.
- Перед сборкой стоит выполнить `npm run lint`.

## Запуск одной программой

Заглушка умеет отдавать собранный сайт сама: всё работает по адресу http://localhost:8080, `npm run dev` не нужен. Так удобно показывать проект.

```
npm run build
cp -R dist /путь/к/папке/сервера/dist
cd /путь/к/папке/сервера
./server_contract
```

При запуске сервер пишет `Frontend: serving ./dist`. Если папки `dist` рядом нет, работает только API.

## Открыть на телефоне и другом устройстве

**В той же сети Wi-Fi:**

```
npm run dev -- --host
```

В терминале появится строка `Network: http://192.168.x.x:5173/` — откройте этот адрес на телефоне. Если Mac спросит про входящие подключения, разрешите. В университетском Wi-Fi устройства часто не видят друг друга — тогда раздайте интернет с телефона и подключите к нему компьютер.

**Из любой сети (временная ссылка):** запустите проект одной программой, затем:

```
brew install cloudflared
cloudflared tunnel --url http://localhost:8080
```

В выводе будет ссылка `https://….trycloudflare.com`. Она работает, пока открыты окна сервера и `cloudflared`. Ссылку видит любой, у кого она есть, — после показа остановите туннель.

## Команды

| Команда | Что делает |
|---|---|
| `npm install` | ставит зависимости (один раз и после изменения `package.json`) |
| `npm run dev` | запускает сайт для разработки, изменения видны сразу |
| `npm run dev -- --host` | то же, но сайт доступен с других устройств в сети |
| `npm run build` | проверяет типы и собирает готовый сайт в `dist/` |
| `npm run preview` | показывает собранную версию из `dist/` |
| `npm run lint` | ищет ошибки в коде (ESLint) |
| `npm run format` | приводит код к единому виду (Prettier) |

    ├── store/              вход, группа, «Помощь», «Форс-мажор» (пока в браузере)
    ├── utils/format.ts     формат денег и дат, ранги задач
    ├── components/
    │   ├── ui/             кнопка, карточка, поле, значок, загрузка, ошибка
    │   ├── Layout.tsx      шапка с логотипом, меню и профилем
    │   ├── Logo.tsx        логотип STATA (SVG)

## Страницы

Порядок экранов повторяет блок-схемы проекта: вход → группа → главная → задачи → аукцион.

| Адрес | Страница | Что там |
|---|---|---|
| `/login` | Вход | вход и регистрация |
| `/groups` | Группа | выбрать группу или создать свою (создатель — админ) |
| `/` | Главная | путь «Задачи → Выполнение → Баллы → Аукцион» |
| `/tasks` | Задачи | лента с фильтрами, рангами и наградой |
| `/tasks/:id` | Задача | взять, сдать, «Помощь», «Форс-мажор», расчёт награды |
| `/auction` | Аукцион | этапы, лоты, ставки, история, баланс |
| `/me` | Профиль | группа, мои задачи, баланс, выход (по аватарке справа) |
| `/demo` | Демо | ползунки ранга и коэффициентов, сервер пересчитывает награду |

Награда считается по формуле библиотеки:

```
Награда = Базовая цена + M × K1 × K2 × K3 − Штраф
M — ранг (D/C/B/A → 1/3/5/10), K1 — время, K2 — силы, K3 — попытки
```

## API

Сайт ждёт от сервера такие адреса (полное описание — в `docs/api.md`):

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/api/tasks` | список задач |
| GET | `/api/tasks/:id` | одна задача |
| GET | `/api/lots` | список лотов |
| GET | `/api/lots/:id` | один лот |
| POST | `/api/lots/:id/bids` | сделать ставку, тело `{ "amount": 120 }` |
| GET | `/api/me` | текущий пользователь |
| POST | `/api/price/preview` | расчёт награды для демо |

Ошибки приходят в одном формате: `{ "error": "bid_too_low", "message": "Ставка должна быть выше текущей" }`. Сайт показывает пользователю `message`.

## Частые проблемы

| Что видно | Причина | Что делать |
|---|---|---|
| «Не удалось связаться с сервером» | сервер не запущен | запустите `./server_contract` в отдельном окне |
| У задач нет ранга, старые цены | запущена старая версия сервера | `Ctrl+C`, заново скомпилируйте и запустите |
| `npm install` падает с ERESOLVE | несовместимые версии пакетов | `npm ci` — ставит версии строго из `package-lock.json` |
| `command not found: npm` | не установлен Node.js | установите Node.js 20.19+ (например, через nvm) |
| Порт 8080 занят | сервер уже запущен в другом окне | закройте старый или найдите его: `lsof -i :8080` |
| «Что-то пошло не так» на странице | ошибка в данных или коде | откройте консоль браузера (Cmd+Option+J) и пришлите текст ошибки |
| 404 при обновлении страницы на хостинге | хостинг не знает про адреса сайта | для Vercel есть `vercel.json`; на другом хостинге нужна переадресация на `index.html` |

## Правила работы с git

- Ветки создаём от `dev`, одна ветка — одна задача: `feature/...`, `fix/...`, `docs/...`.
- Pull request открываем только в `dev`, в `main` нельзя.
- Коммиты в формате `тип(область): описание`, например `feat(tasks): add task card`. Типы: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`.
- Перед pull request: `npm run format`, `npm run lint`, `npm run build`.

Подробнее — `CONTRIBUTING.ru.md` в репозитории команды.
